# 최소 힙 (Min-Heap) 및 TTL 만료 관리 기법 정리

본 문서는 필기 노트와 소스 코드 분석을 바탕으로, **힙(Heap)의 기본 정의와 종류(최대 힙/최소 힙)**, **배열 인덱스 산술 공식**, **트리 다이어그램을 통한 삽입(상향 재정렬) 및 삭제(하향 재정렬) 단계별 시각화**, 그리고 Mini-Redis의 **TTL(Time-To-Live) 만료 관리**와 **지연 삭제(Lazy Invalidation)** 전략을 완벽 정리한 학습 문서입니다.

---

## 1. 힙(Heap)의 기본 개념 

- **정의**: **완전 이진 트리(Complete Binary Tree)**의 일종으로, **우선순위 큐(Priority Queue)**를 구현하기 위해 고안된 자료구조입니다.
  - 데이터 추가 시 항상 **왼쪽부터 빈틈없이** 채워집니다.
  - 부모 노드의 값이 자식 노드의 값보다 항상 크거나 작도록 유지하는 느슨한 정렬(반정렬) 상태를 유지합니다.
- **목적**: 여러 개의 값들 중에서 **최댓값 또는 최솟값을 $O(1)$의 속도로 빠르게 찾아내기 위함**입니다.
- **장점**: 
  - 복잡한 포인터(`left`, `right`) 없이 **인덱스 계산만으로 부모-자식을 즉각 찾아갈 수 있습니다**.
  - 완전 이진 트리의 특성 덕분에 빈틈없는 **1차원 연속 배열**로 완벽하게 표현할 수 있어 메모리 효율과 캐시 지역성이 뛰어납니다.

---

## 2. 힙의 종류: 최대 힙 vs 최소 힙 

### 1) 최대 힙 (Max-Heap)
- **규칙**: 부모 노드의 키 값 $\ge$ 자식 노드의 키 값
- **특징**: 루트(인덱스 0)에 전체 원소 중 **가장 큰 최댓값**이 위치합니다.

```text
[최대 힙 트리 구조]
              [9] (i=0)
             /   \
      (i=1) [7]   [6] (i=2)
           /   \  /  \
    (i=3) [5]  [4][3] [2] (i=6)
         /
  (i=7) [2]

배열 상태 = [ 9, 7, 6, 5, 4, 3, 2, 2 ]
```

---

### 2) 최소 힙 (Min-Heap) — Mini-Redis 채택
- **규칙**: 부모 노드의 키 값 $\le$ 자식 노드의 키 값
- **특징**: 루트(인덱스 0)에 전체 원소 중 **가장 작은 최솟값**이 위치합니다.

```text
[최소 힙 트리 구조]
              [1] (i=0)
             /   \
      (i=1) [4]   [2] (i=2)
           /   \  /  \
    (i=3) [7]  [5][3] [3] (i=6)
         /  \   /
  (i=7) [7] [8][9] (i=9)

배열 상태 = [ 1, 4, 2, 7, 5, 3, 3, 7, 8, 9 ]
```

---

## 3. 완전 이진 트리의 배열 인덱스 산술 공식

배열의 인덱스가 $0$번부터 시작할 때, 현재 노드의 위치 $i$만 알면 부모와 자식의 위치는 수학적으로 즉각 도출됩니다.

```text
               [0] 루트 (i=0)
              /   \
         [1] (i=1) [2] (i=2)
        /   \      /   \
      [3]   [4]  [5]   [6]
```

- **부모 노드 인덱스**: $\lfloor(i - 1) / 2\rfloor$
- **왼쪽 자식 인덱스**: $2i + 1$
- **오른쪽 자식 인덱스**: $2i + 2$

###  부모 인덱스 공식 통일 증명 (필기 노트 내용)
- 왼쪽 자식 $c = 2i + 1 \implies i = \frac{c - 1}{2}$
- 오른쪽 자식 $c = 2i + 2 \implies i = \frac{c - 2}{2}$
- 정수 나눗셈 `// 2`는 소수점을 버리므로 오른쪽 자식의 $\frac{c-2}{2}$ 역시 $\lfloor\frac{c-1}{2}\rfloor$과 같습니다.
- 따라서 좌·우 자식 구분 없이 **`(c - 1) // 2`라는 단일 공식**으로 통일됩니다.

## 4. 원소 삽입 3단계 및 상향 재정렬(Up-Heap) 트리 시각화

### 1) 삽입 3단계 규칙 (노트 필기 내용)
1. **가장 왼쪽 빈 자리(배열의 맨 끝)**에 새 값을 추가합니다.
2. **부모와 비교하며 위로 올라갑니다** (부모보다 작으면 맞교환).
3. **부모보다 커지는 지점에서 멈춥니다**.

---

### 2) 상향 재정렬(`_heapify_up`) 단계별 트리 전이도
- **상황 예시**: `push(5)` 실행 (현재 인덱스 0~8까지 차 있는 상태에서 9번 인덱스에 신규 데이터 `5` 삽입)

#### [초기 상태: 맨 끝(인덱스 9)에 5 추가]
```text
                  [10] (i=0)
                 /    \
           [15] (i=1)  [20] (i=2)
           /    \      /    \
        [25]    [30] [35]   [40]
        /  \    /
     [45] [50] [ 5 ]* (i=9, 신규 삽입!)
```

#### [1차 교환: 9번(5)과 부모 4번(30) 비교 $\rightarrow$ 5 < 30 맞교환]
- 부모 인덱스: $(9 - 1) // 2 = 4$번 `[30]`
- `5 < 30`이므로 위치 스왑! 현재 5의 위치: 인덱스 4

```text
                  [10] (i=0)
                 /    \
           [15] (i=1)  [20] (i=2)
           /    \      /    \
        [25]   [ 5 ]* [35]  [40]
        /  \    /
     [45] [50] [30]
```

#### [2차 교환: 4번(5)과 부모 1번(15) 비교 $\rightarrow$ 5 < 15 맞교환]
- 부모 인덱스: $(4 - 1) // 2 = 1$번 `[15]`
- `5 < 15`이므로 위치 스왑! 현재 5의 위치: 인덱스 1

```text
                  [10] (i=0)
                 /    \
           [ 5 ]* (i=1)[20] (i=2)
           /    \      /    \
        [25]    [15]  [35]  [40]
        /  \    /
     [45] [50] [30]
```

#### [3차 교환: 1번(5)과 부모 0번(10) 비교 $\rightarrow$ 5 < 10 맞교환 (루트 등극)]
- 부모 인덱스: $(1 - 1) // 2 = 0$번 `[10]`
- `5 < 10`이므로 위치 스왑! 현재 5의 위치: 인덱스 0 (루트 도착, 종료)

```text
                 [ 5 ]* (i=0, 최종 안착!)
                 /    \
           [10] (i=1)  [20] (i=2)
           /    \      /    \
        [25]    [15]  [35]  [40]
        /  \    /
     [45] [50] [30]
```
- **시간 복잡도**: 트리의 높이($\log_2 N$)만큼만 교환되므로 **$O(\log N)$**입니다.

## 5. 최솟값 삭제(루트 제거) 및 하향 재정렬(Down-Heap) 트리 시각화

### 1) 삭제 2단계 규칙 
1. 루트 노드를 꺼낸 뒤, **배열의 마지막 원소를 루트(인덱스 0)로 순간이동**시킵니다.
2. **자식과 비교하며 아래로 내려갑니다(`_heapify_down`)** (두 자식 중 더 작은 자식과 교환).

> * 왜 마지막 원소를 루트로 올릴까?**  
> 빈 루트를 채우려고 앞쪽 노드들을 한 칸씩 당기면 $O(N)$의 이동 비용이 들고 트리의 부모-자식 인덱스 규칙이 무너집니다. 따라서 맨 끝 요소를 올려 트리 형태를 보존한 채 $O(\log N)$으로 가라앉히는 것입니다.

---

### 2) 하향 재정렬(`_heapify_down`) 단계별 트리 전이도
- **상황 예시**: 루트 노드 `[1]`을 삭제(`pop()`)하고 마지막 노드 `[30]`을 루트로 이동시킨 상황

#### [초기 상태: 루트 [1] 제거 후 맨 끝 원소 [30]을 루트로 이동]
```text
                 [30]* (i=0, 임시 루트)
                 /    \
           [ 4 ] (i=1) [ 2 ] (i=2)
           /    \      /    \
        [ 7 ]   [ 5 ] [ 3 ]  [ 8 ]
```

#### [1차 교환: 0번(30)과 두 자식(1번:4, 2번:2) 비교 $\rightarrow$ 가장 작은 2번(2)과 맞교환]
- 왼쪽 자식(4), 오른쪽 자식(2) 중 최솟값은 2번 `[2]`
- `30 > 2`이므로 위치 스왑! 현재 30의 위치: 인덱스 2

```text
                 [ 2 ] (i=0)
                 /    \
           [ 4 ] (i=1)[30]* (i=2)
           /    \      /    \
        [ 7 ]   [ 5 ] [ 3 ]  [ 8 ]
```

#### [2차 교환: 2번(30)과 두 자식(5번:3, 6번:8) 비교 $\rightarrow$ 가장 작은 5번(3)과 맞교환]
- 왼쪽 자식 $2 \times 2 + 1 = 5$번 `[3]`
- 오른쪽 자식 $2 \times 2 + 2 = 6$번 `[8]`
- 두 자식 중 더 작은 값은 `[3]`. `30 > 3`이므로 위치 스왑! 현재 30의 위치: 인덱스 5

```text
                 [ 2 ] (i=0)
                 /    \
           [ 4 ] (i=1) [ 3 ] (i=2)
           /    \      /    \
        [ 7 ]   [ 5 ] [30]*  [ 8 ]
```
- 더 이상 자식이 없으므로 재정렬 종료!
- **시간 복잡도**: 아래로 내려갈 때도 트리의 높이만큼 하강하므로 **$O(\log N)$**입니다.

## 6. Mini-Redis TTL 만료 관리와 최소 힙의 결합

### 1) $O(1)$ 감시 메커니즘: `_clean_expired()`
Mini-Redis의 저장 원소는 `(expire_at, key)` 튜플 형태로 저장됩니다.

```python
def _clean_expired(self):
    current_time = time.time()
    while not self.ttl_heap.is_empty():
        peek_item = self.ttl_heap.peek()   # O(1) 루트 노드 확인
        expire_at, key = peek_item

        # 꼭대기 노드마저 아직 만료 전이라면?
        if expire_at > current_time:
            break                          # 뒤의 수만 개는 볼 것도 없이 즉시 종료! O(1)

        self.ttl_heap.pop()                # 만료된 키는 O(log N)으로 꺼내어 DB에서 제거
        ...
```
- 수만 개의 키가 있어도 매초 전체 배열을 뒤지는 $O(N)$ 전수 조사를 하지 않습니다.
- **루트 노드 하나만 확인(`peek()`, $O(1)$)**하여 검사를 끝내므로 압도적인 성능을 보장합니다.

---

### 2) 힙 지연 삭제 (Lazy Invalidation) 전략

- **문제점**:
  - `DEL key`가 실행되거나, 사용자가 `SET key "new"`로 만료 시간을 갱신했을 때, 힙 내부의 중간 노드를 직접 찾아 수정하거나 삭제하려면 힙 배열 전체를 순회해야 하므로 **$O(N)$의 치명적인 병목**이 발생합니다.
- **해결책**:
  1. 힙 내부는 건드리지 않고 방치합니다.
  2. 별도의 장부(`self.key_ttl[key] = 최신시각`)에만 최신 만료 시각을 갱신하거나 지웁니다.
  3. 시간이 흘러 해당 노드가 힙의 꼭대기(루트)로 올라왔을 때 장부와 대조합니다:
     ```python
     # 힙에 적힌 시각과 장부에 적힌 진짜 최신 만료 시각이 다르다면?
     if hasattr(self, "key_ttl") and key in self.key_ttl and self.key_ttl[key] != expire_at:
         continue  # 쓸모없어진 옛날 찌꺼기(유령 노드)이므로 무시하고 버림
     ```
  4. 이를 통해 비싼 힙 중간 삭제 비용($O(N)$)을 완벽히 회피합니다.
