# 02. 기반 선형 자료구조 - 동적 배열 및 이중 연결 리스트

본 문서는 Mini-Redis의 기초 바닥을 구성하는 동적 배열(`dynamic_array.py`), 더미 노드 기반 이중 연결 리스트(`doubly_linked_list.py`), 그리고 이를 부품으로 삼아 구현된 선형 구조 3형제(스택, 큐, 덱, `linear_structures.py`)를 상세히 분석합니다.

---

## 1. 동적 배열 (`dynamic_array.py`)

### 1) 개념 및 필요성
- **What?**: 고정된 크기의 배열이 가득 차면, 용량(Capacity)을 2배로 늘린 새 배열을 할당하여 기존 요소들을 통째로 복사·이전시키는 동적 크기 확장 메커니즘입니다.
- **Where?**: `hash_map.py`의 버킷 배열(`self.buckets`)과 `min_heap.py`의 내부 저장소(`self.heap`)에 파이썬 내장 리스트 대신 적용됩니다.

### 2) 분할 상환 시간 복잡도 (Amortized $O(1)$)
- 크기를 늘리고 전체 데이터를 복사할 때는 일시적으로 $O(N)$의 시간이 소요됩니다.
- 그러나 용량을 2배씩 늘리기 때문에 리사이징이 발생하는 주기는 기하급수적으로 길어집니다.
- 연속된 $N$번의 삽입에 드는 총 복사 비용을 평균 내면, 데이터 1회 추가당 비용은 **분할 상환 $O(1)$**로 수렴합니다.

### 3) 매직 메서드(Magic Methods)를 통한 내장 리스트 호환
`MinHeap`이나 `HashMap` 내부 코드를 뜯어고치지 않고 파이썬 내장 리스트처럼 대괄호 인덱싱(`[]`)을 그대로 사용하기 위해 다음 매직 메서드를 구현합니다:
- `__getitem__(self, index)`: `arr[i]` 조회를 가로채 $O(1)$로 반환.
- `__setitem__(self, index, value)`: `arr[i] = val` 대입을 가로채 $O(1)$로 수정.
- `__len__(self)`: `len(arr)` 호출 시 현재 저장된 실제 데이터 개수를 반환.

## 2. 이중 연결 리스트 (`doubly_linked_list.py`)

### 1) 단일 연결 리스트 vs 이중 연결 리스트
- **단일 연결 리스트**: 다음 노드를 가리키는 `next` 포인터 하나만 존재합니다. 마지막 노드에 추가하거나 삭제하려면 Head부터 끝까지 타고 가야 하므로 $O(N)$이 걸릴 수 있습니다.
- **이중 연결 리스트**: 앞 노드를 가리키는 `prev`와 뒷 노드를 가리키는 `next`를 모두 갖춥니다. 항상 `tail` 포인터를 함께 유지하므로 양방향 이동이 가능하며 끝단 삽입/삭제를 $O(1)$에 수행합니다.

### 2) 더미 노드(Dummy/Sentinel Node) 유무 비교

노트 필기에서 가장 중요하게 다룬 핵심 최적화 기법입니다. 양 끝에 실제 데이터를 담지 않는 빈 껍데기 노드(`Head Dummy`, `Tail Dummy`)를 영구 배치합니다.

```text
[더미 노드가 없을 때]
  head -----> [ Node A ] <=====> [ Node B ] <----- tail
              (prev: None)        (next: None)

[더미 노드가 있을 때]
  [Head Dummy] <=====> [ Node A ] <=====> [ Node B ] <=====> [Tail Dummy]
```

| 비교 항목 | 더미 노드 미사용 (No Dummy) | 더미 노드 사용 (Dummy Node) |
| :--- | :--- | :--- |
| **초기 상태 (데이터 0개)** | `head = None`, `tail = None` | `head`와 `tail` 객체가 존재하며 서로 맞물려 연결됨 |
| **양 끝단 포인터** | 첫 노드의 `prev = None`, 끝 노드의 `next = None` | 데이터 노드의 바깥 포인터는 항상 더미 노드를 가리킴 |
| **예외 분기 처리** | 삽입/삭제 시마다 `if self.head is None:` 등 분기 필수 | 노드가 0개이든 여러 개이든 동일한 포인터 재연결 로직 적용 |
| **안정성** | 실수로 포인터가 끊기면 `NullPointerException` 위험 | 경계 조건(Edge cases)이 완전히 제거되어 안전함 |

### 3) 주요 연산 시간 복잡도 비교표

| 연산 | 이중 연결 리스트 | 단일 연결 리스트 | 동적 배열 (Array) |
| :--- | :---: | :---: | :---: |
| **임의 인덱스 접근 (Access)** | $O(N)$ | $O(N)$ | **$O(1)$** |
| **탐색 (Search)** | $O(N)$ | $O(N)$ | $O(N)$ |
| **노드 주소를 알 때 삽입 (Insert)** | **$O(1)$** | **$O(1)$** | $O(N)$ (데이터 시프트 필요) |
| **노드 주소를 알 때 삭제 (Delete)** | **$O(1)$** | $O(N)$ (이전 노드 추적 필요) | $O(N)$ (데이터 시프트 필요) |

## 3. 선형 구조 3형제 (`linear_structures.py`)

`DoublyLinkedList`를 내부 부품으로 품어 겉모습만 변환하는 **어댑터(Adapter) / 컴포지션(Composition) 패턴**을 적용하여 구현합니다.

### 1) 세 자료구조 한눈에 비교

| 자료구조 | 입·출력 원칙 | 동작 방식 | 비유 | 주요 활용처 in 프로젝트 |
| :--- | :---: | :--- | :--- | :--- |
| **스택 (Stack)** | **LIFO** (후입선출) | 한쪽 끝(Top)에서만 넣고 뺌 | 프링글스 감자칩 통 | 뒤로가기, 함수 호출 스택, 괄호 검사 |
| **큐 (Queue)** | **FIFO** (선입선출) | 뒤로 넣고 앞으로 뺌 | 은행 대기표 창구 | `pubsub.py` 메시지 버퍼, `binary_tree.py` 레벨 순회 |
| **덱 (Deque)** | **양방향 자유** | 앞/뒤 양쪽 끝 모두에서 넣고 뺌 | 양쪽이 뚫린 터널 | 스택/큐 만능 대체재, Redis List 자료형 구현 |

### 2) 이중 연결 리스트 메서드와의 1:1 대응 매핑표

일반 배열로 큐나 덱을 만들면 앞에서 꺼낼 때 빈자리를 채우기 위해 뒤 요소를 당겨오는 $O(N)$ 지연이 발생합니다. 하지만 더미 노드 기반 이중 연결 리스트를 사용하면 모든 연산이 순수한 $O(1)$로 보장됩니다.

| 선형 자료구조 | 연산 인터페이스 | 이중 연결 리스트 호출 메서드 | 시간 복잡도 |
| :--- | :--- | :--- | :---: |
| **Stack** | `push(item)` | `insert_front(key=item, value=None)` | $O(1)$ |
| | `pop()` | `remove_front()` | $O(1)$ |
| | `peek()` | `self.head.next.key` (헤드 다음 노드 데이터 조회) | $O(1)$ |
| **Queue** | `enqueue(item)` | `insert_back(key=item, value=None)` | $O(1)$ |
| | `dequeue()` | `remove_front()` | $O(1)$ |
| | `peek()` | `self.head.next.key` (헤드 다음 노드 데이터 조회) | $O(1)$ |
| **Deque** | `append_front(item)`| `insert_front(key=item, value=None)` | $O(1)$ |
| | `append_back(item)` | `insert_back(key=item, value=None)` | $O(1)$ |
| | `pop_front()` | `remove_front()` | $O(1)$ |
| | `pop_back()` | `remove_back()` | $O(1)$ |
