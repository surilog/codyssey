

#  알고리즘 복잡도 & 빅오(Big-O) 표기법 요약 노트

## 1. 빅오(Big-O) 표기법의 개념

알고리즘의 효율성을 평가할 때 핵심은 "입력 데이터의 크기 $n$이 커질 때 수행 단계(시간/메모리)가 얼마나 증가하는가"이다. 이를 대략적(점근적)으로 나타내는 표기법을 점근 표기법이라고 한다.

> ** 대략적이라는 의미**
> 엉터리로 계산한다는 뜻이 아니라, 데이터가 무한히 커질 때 성능에 결정적인 영향을 미치는 
**가장 지배적인 항목(최고차항)**에만 집중하고 수식의 작은 숫시(상수/하위항)를 생략한다는 의미

### 점근 표기법 3가지

* **$O$ (Big-O, 빅오):** 최악의 경우(수행 시간의 상한선). **가장 널리 사용됨.** (최소한 이 성능은 보장된다는 의미)
* **$\Omega$ (Big-Omega, 빅 오메가):** 최선의 경우(수행 시간의 하한선).
* **$\Theta$ (Big-Theta, 빅 세타):** 상한선과 하한선을 동시에 만족하는 평균적인 성능.

## 2. 시간 복잡도 등급 비교

효율성이 가장 높은 순서($O(1)$)부터 가장 낮은 순서($O(c^n)$) 순으로 정리된 표입니다.

| 표기법 | 명칭 | 특징 및 대표 사례 | $n=1,000$ 일 때 대략적 연산 횟수 |
| --- | --- | --- | --- |
| **$O(1)$** | **상수 시간** (Constant) | 입력 크기와 상관없이 항상 일정한 단계 수행 (예: 리스트 첫 요소 접근) | $1$ |
| **$O(\log n)$** | **로그 시간** (Logarithmic) | 연산마다 탐색 범위를 $1/2$씩 줄여나감 (예: 이진 탐색) | $\approx 10$ |
| **$O(n)$** | **선형 시간** (Linear) | 입력 크기에 비례하여 단계가 늘어남 (예: 전체 목록 1회 탐색) | $1,000$ |
| **$O(n \log n)$** | **선형 로그 시간** | $O(\log n)$ 알고리즘을 $n$번 반복함 (예: 병합 정렬, 퀵 정렬) | $\approx 10,000$ |
| **$O(n^2)$** | **2차 시간** (Quadratic) | 이중 중첩 루프 구조 (예: 버블 정렬, 삽입 정렬) | $1,000,000$ |
| **$O(n^3)$** | **3차 시간** (Cubic) | 삼중 중첩 루프 구조 (예: 다차원 행렬 곱셈) | $1,000,000,000$ |
| **$O(2^n)$ / $O(c^n)$** | **지수 시간** (Exponential) | $n$이 증가함에 따라 단계가 폭발적으로 급증 (예: 무차별 대입/Brute-force) | $2^{1000}$ (상당히 거대함) |

## 3. 대표적인 시간 복잡도별 코드 예시 (Python)

### ① $O(1)$ — 상수 시간 (Constant Time)

```python
# 리스트에 데이터가 아무리 많아도 첫 번째 요소만 바로 출력
def get_first_item(items):
    first = items[0]
    return first


print(get_first_item([10, 20, 30, 40, 50]))  # 출력: 10

```

### ② $O(\log n)$ — 로그 시간 (Logarithmic Time)

```python
# 1부터 100까지 정렬된 숫자 중 77을 찾는 과정 (이진 탐색)
def binary_search(numbers, target):
    left = 0
    right = len(numbers) - 1

    while left <= right:
        mid = (left + right) // 2  # 중간 위치 찾기

        if numbers[mid] == target:
            return mid  # 찾았음!
        elif numbers[mid] < target:
            left = mid + 1  # 중간보다 크면 오른쪽 반만 탐색
        else:
            right = mid - 1  # 중간보다 작으면 왼쪽 반만 탐색

    return -1


numbers = [10, 20, 30, 40, 50, 60, 70, 80, 90]
print(binary_search(numbers, 70))  # 70이 위치한 인덱스 출력

```

### ③ $O(n)$ — 선형 시간 (Linear Time)

```python
# 리스트의 모든 숫자를 하나씩 더합니다.
def sum_all(numbers):
    total = 0
    for num in numbers:  # 숫자가 5개면 5번, 1,000개면 1,000번 실행
        total = total + num
    return total


print(sum_all([1, 2, 3, 4, 5]))  # 출력: 15

```

### ④ $O(n^2)$ — 2차 시간 (Quadratic Time)

```python
# 리스트 안의 모든 숫자 쌍을 조합해서 출력합니다.
def print_all_pairs(numbers):
    for i in numbers:  # 첫 번째 루프 (n번)
        for j in numbers:  # 두 번째 루프 (n번) -> 총 n * n 번
            print(i, j)


# 데이터 3개 -> 총 3 x 3 = 9번 출력
print_all_pairs([1, 2, 3])

```

### ⑤ $O(10^n)$ — 지수 시간 (Exponential Time / Brute-Force)

```python
# n자리 비밀번호(0~9)를 찾기 위해 모든 경우의 수를 하나씩 맞춰봅니다.
def crack_password(length):
    # length가 1이면 10번 (10^1)
    # length가 2면 100번 (10^2)
    # length가 3이면 1,000번 (10^3)
    total_try = 10**length

    count = 0
    for i in range(total_try):
        count += 1
    return count


print(crack_password(3))  # 3자리 비밀번호 시도 횟수: 1000번

```

## 4. 공간 복잡도 (Space Complexity)

알고리즘을 실행할 때 **컴퓨터 메모리를 얼마나 사용하는지** 나타냅니다.

* **고정 공간 (Fixed Space):** 프로그램 자체, 단순 변수가 차지하는 공간.
* **자료구조 공간 (Data Structure Space):** 입력 데이터를 저장하는 데 필요한 공간.
* **임시 공간 (Temporary Space):** 계산 과정에서 생기는 사본이나 임시 배열.

### 공간 복잡도 예시

* **$O(1)$ 공간 복잡도:** 입력 데이터 $n$이 아무리 커져도 메모리 사용량이 일정한 경우 (예: 반복문 내부의 변수 1~2개 사용)
* **$O(n)$ 공간 복잡도:** $n$개의 결과값을 저장하기 위해 $n$ 크기의 새로운 리스트를 만드는 경우

## 5. 핵심 요약 & 알고리즘 최적화 팁

1. **내부 루프 문장 수정보다 "차수(계수) 낮추기"가 우선**
* 중첩 루프 $O(n^2)$ 내부 코드를 미세하게 튜닝하는 것보다, 알고리즘 구조를 변경해 $O(n)$이나 $O(n \log n)$으로 바꾸는 것이 성능 개선 효과가 훨씬 큽니다.


2. **최악의 경우(Worst-case)를 기준으로 대비**
* 데이터의 형태나 상황에 따라 성능 변동이 크더라도 빅오($O$) 표기법인 최악의 경우를 알아두어야 시스템 마비나 응답 지연을 방지할 수 있습니다.


3. **규모(Scale)에 집중**
* 데이터 소규모 시점에는 정렬 알고리즘 간 차이가 크지 않으나, 데이터가 급증하는 서비스 환경에서는 복잡도가 서비스 성능을 결정짓습니다.
