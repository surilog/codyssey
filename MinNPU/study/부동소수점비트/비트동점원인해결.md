
#  Floating-Point MAC 연산 비트 동점(UNDECIDED) 이슈 분석 및 해결 보고서

##  Executive Summary (개요)
본 프로젝트는 NPU 및 패턴 매칭 시뮬레이터의 MAC(Multiply-Accumulate) 연산 수행 중, 특정 패턴 입력에서 Cross 필터 점수와 X 필터 점수가 하위 비트(ULP)까지 100% 동일하여 **`UNDECIDED` (동점) 판정으로 실패(FAIL)하는 현상**을 분석하고 이를 시스템적으로 해소한 과정을 다룹니다.

---

##  1. 기존 프로그램에서 문제가 발생한 이유

기존 프로그램에서는 파이썬 내장 함수인 **`sum()`과 제너레이터(Generator)** 표현식을 사용하여 MAC 연산을 처리했습니다.

```python
# 기존 연산 방식 (sum() 및 제너레이터 사용)
total_sum = sum(
    filter_data[r][c] * pattern_data[r][c]
    for r in range(n) for c in range(n)
)

```

이 방식은 아래 두 가지 원인이 결합하면서 비트 단위 완전 동점(Hex 100% 일치)을 유발했습니다.

1. **데이터셋의 공간적 대칭성 (Data Symmetry)**
* 입력 패턴과 필터(Cross, X)가 행렬 내에서 **대칭 구조**를 이룸에 따라, 두 연산 간에 합산되는 원소들의 가중치 조합이 이론적으로 완전히 동일해짐.


2. **C-level 연산 파이프라인과 IEEE 754 수렴**
* CPython의 `sum()` C-API 연산 파이프라인은 고속 레지스터에서 연속 누적을 수행함.
* 대칭 데이터셋의 연산 중간 오차가 C-level 레지스터 누적 끝에 **IEEE 754 'Round-to-Nearest-Even' 반올림 규칙**에 의해 동일한 비트 오프셋으로 수렴 정리되어 버림.

##  2. 부동소수점 기초 원리 및 연산 저울 비교 실험

MAC 연산에서 발생하는 수렴 현상의 원인을 규명하기 위해 진행한 3가지 기초 실험 결과입니다.

1. **실험 1 (2진수 무한소수 절삭):** 10진수 소수($0.1, 0.2$ 등)는 2진수로 변환 시 무한소수가 되므로 52비트 가수부 경계에서 잘림.
2. **실험 2 (`sum()` vs `loop()` 저울 차이):** C-level 레지스터를 사용하는 `sum()`과 Python 객체 레벨의 `for` 루프 누적 차이.
3. **실험 3 (가수부 경계 절삭 - Round to Even):** 순서에 따라 $2^{53}$ 수준의 큰 수와 작은 수의 합산 시 하위 비트 소멸 현상 발생.

### 2.1 기초 실험 코드

```python
import struct

def get_hex(num):
    return num.hex()

# 1. 2진수로 딱 떨어지지 않는 소수점 데이터 (실제 MAC 연산과 유사한 데이터)
# 0.1, 0.2 등은 2진수로 무한소수이므로 무조건 52비트 경계에서 잘립니다.
cross_data = [0.1, 0.2, 0.3, 0.4, 0.1, 0.2, 0.3, 0.4] * 100
x_data     = [0.4, 0.3, 0.2, 0.1, 0.4, 0.3, 0.2, 0.1] * 100

# 2. C-level sum() 연산
cross_sum = sum(cross_data)
x_sum     = sum(x_data)

# 3. 명시적 루프(loop) 연산
cross_loop = 0.0
for val in cross_data:
    cross_loop += val

print("=== 1. sum()을 썼을 때 Cross vs X 비교 ===")
print(f"Cross sum Hex : {get_hex(cross_sum)}")
print(f"X sum Hex     : {get_hex(x_sum)}")
print(f"비트 동일 여부: {get_hex(cross_sum) == get_hex(x_sum)}")

print("\n=== 2. 같은 Cross 데이터에서 sum() vs loop() 비교 ===")
print(f"sum() 결과  Hex : {get_hex(cross_sum)}")
print(f"loop() 결과 Hex : {get_hex(cross_loop)}")
print(f"두 결과가 같은가? : {get_hex(cross_sum) == get_hex(cross_loop)}")

# 1. 2^53 (약 90조, 53비트 가수부가 꽉 찬 상태)
big_num = float(2**53)

# 2. 아주 작은 미세 수들 (1.0)
small_nums = [1.0] * 5

# --- [방식 A] 큰 수를 먼저 더하기 ---
# big_num에 1.0을 더할 때마다 52비트 경계선 밖으로 밀려나서 1.0이 싹 잘려 나가지게 됨.
sum_A = big_num
for s in small_nums:
    sum_A += s

# --- [방식 B] 작은 수들을 먼저 다 더하고, 나중에 큰 수 더하기 ---
# 1.0 5개가 먼저 더해져 5.0이 된 후 big_num과 합쳐지므로 비트가 살아남음.
small_total = 0.0
for s in small_nums:
    small_total += s
sum_B = small_total + big_num

print("\n=== 100% 비트 차이 검증 ===")
print(f"방식 A (큰 수 먼저) Hex : {sum_A.hex()}")
print(f"방식 B (작은 수 먼저) Hex : {sum_B.hex()}")
print(f"10진수 표기 - 방식 A: {sum_A} | 방식 B: {sum_B}")
print(f"두 결과가 완벽히 같은가? : {sum_A.hex() == sum_B.hex()}")

```

##  3. 핵심 원인 분석: 데이터 대칭성 및 연산 방식 비교

### ① 데이터셋 구조 (대칭 vs 비대칭)

* **대칭 데이터셋 (`size_5_1`, `size_13_2` 등):** 원소 위치상 대칭을 이루므로 `sum()` 파이프라인 적용 시 하위 비트 오차가 완전 수렴하여 **동점(`UNDECIDED` / FAIL) 발생**.
* **비대칭 데이터셋:** 원소 위치 및 가중치 분포가 불균형하므로 `sum()`을 사용하더라도 누적 점수와 비트가 달라져 **정상 분류(PASS)**.

### ② 연산 파이프라인 차이 (`sum()` vs `loop()`)

| 구분 | `sum()` 제너레이터 방식 | `loop()` 명시적 루프 방식 |
| --- | --- | --- |
| **연산 레벨** | CPython C-API 레벨 연속 연산 | 파이썬 인터프리터 Float 객체 레벨 |
| **연산 순서 영향** | 행 우선 순회 오차가 C-레지스터 수렴 과정에서 제거됨 | **행 우선 순회 오차(ULP 오프셋)가 매 Step마다 보존됨** |
| **결합법칙 미성립** | 수렴에 의해 영향 없음 | **연산 순서 차이에 의한 미세 오차가 누적되어 오프셋 발생** |
| **비트 일치 여부** | `True` (완벽 일치 $\rightarrow$ **FAIL**) | `False` (비트 갈라짐 $\rightarrow$ **PASS**) |

---
### ③ CPython 내장 sum()의 구현 동작 및 버전별 변경 사항 (Python Spec)
Python Official Docs - sum()에 명시된 주요 변경 내역과 구현 동작은 본 이슈의 원인을 이론적으로 뒷받침합니다.

CPython 연속 누적 방식:
sum()은 내부적으로 C 레벨의 연속 누적기를 활용하며, 요소들을 합산하는 과정에서 정밀도 손실 및 반올림(Round-to-Nearest-Even) 처리가 정교하게 실행됩니다.

버전별 주요 변경 이력:

Python 3.8: start 매개변수를 키워드 인자(Keyword Argument)로 지정할 수 있도록 변경되었습니다. (sum(iterable, /, start=0))

Python 3.12: 부동소수점(float) 합산 시 높은 정밀도와 뛰어난 교환법칙(Better Commutativity)을 제공하는 알고리즘으로 전환되었습니다. 이로 인해 순서가 다른 대칭 데이터셋이라도 대부분의 빌드 환경에서 동일한 부동소수점 비트값으로 더 완벽하게 수렴하여 동점(UNDECIDED)이 유발될 확률이 높아졌습니다.

Python 3.14: 복소수(complex) 합산 연산에도 float과 동일한 고정밀 알고리즘 최적화(Specialization)가 적용되었습니다.

##  4. 검증 코드 및 결과 (Execution Code & Output)

### 4.1 Step별 원소 곱셈값 및 비트 변화 추적 코드

```python
import json

# 1. JSON 데이터 로드
with open('data.json', 'r', encoding='utf-8') as f:
    json_data = json.load(f)

pattern = json_data["patterns"]["size_5_1"]["input"]
x_filter = json_data["filters"]["size_5"]["x"]
cross_filter = json_data["filters"]["size_5"]["cross"]
n = 5

print("========================================================================================================================")
print("  [size_5_1] Step별 원소 곱셈값(Term) + sum() C-level 수렴 vs loop() 오차 보존 대조")
print("========================================================================================================================")

# loop 연산용 누적 변수
loop_x = 0.0
loop_cross = 0.0

# sum 시뮬레이션용 데이터
x_terms = [x_filter[r][c] * pattern[r][c] for r in range(n) for c in range(n) if (x_filter[r][c] * pattern[r][c] != 0 or cross_filter[r][c] * pattern[r][c] != 0)]
cross_terms = [cross_filter[r][c] * pattern[r][c] for r in range(n) for c in range(n) if (x_filter[r][c] * pattern[r][c] != 0 or cross_filter[r][c] * pattern[r][c] != 0)]

step = 0
for r in range(n):
    for c in range(n):
        vx = x_filter[r][c] * pattern[r][c]
        vc = cross_filter[r][c] * pattern[r][c]
        
        if vx != 0 or vc != 0:
            step += 1
            # 1. loop() 누적 (파이썬 float 객체 레벨)
            loop_x += vx
            loop_cross += vc
            
            # 2. sum() 연속 누적 시뮬레이션 (C-level 파이프라인)
            sum_x_sim = sum(x_terms[:step])
            sum_cross_sim = sum(cross_terms[:step])

            print(f" Step {step:02d} | 위치 ({r},{c})  ==>  [이번 Step 곱한값] Cross: {vc:.1f} | X: {vx:.1f}")
            print(f" ├─ [loop()] 오차 보존  | Cross: {loop_cross:<18} ({loop_cross.hex()}) vs X: {loop_x:<18} ({loop_x.hex()})")
            print(f" ├─ [sum() ] C-연속 누적 | Cross: {sum_cross_sim:<18} ({sum_cross_sim.hex()}) vs X: {sum_x_sim:<18} ({sum_x_sim.hex()})")
            print(f" └─ 현재 비트 동점 여부   | loop(): {loop_cross.hex() == loop_x.hex()} | sum(): {sum_cross_sim.hex() == sum_x_sim.hex()}")
            print("-" * 120)

# 최종 실제 CPython sum() 및 loop() 비교
real_sum_x = sum(x_filter[r][c] * pattern[r][c] for r in range(n) for c in range(n))
real_sum_cross = sum(cross_filter[r][c] * pattern[r][c] for r in range(n) for c in range(n))

print("\n========================================================================================================================")
print(" 최종 결과 및 동점(UNDECIDED) 판정")
print("========================================================================================================================")
print(" [sum() 방식 - C-level 파이프라인]")
print(f"  ├─ Cross 점수 : {real_sum_cross:<20} | Hex: {real_sum_cross.hex()}")
print(f"  ├─ X     점수 : {real_sum_x:<20} | Hex: {real_sum_x.hex()}")
print(f"  └─ 판정: 반올림 규칙에 의해 완벽히 수렴함 => {real_sum_cross.hex() == real_sum_x.hex()} ( UNDECIDED / FAIL)")
print()
print(" [loop() 방식 - 파이썬 오차 보존]")
print(f"  ├─ Cross 점수 : {loop_cross:<20} | Hex: {loop_cross.hex()}")
print(f"  ├─ X     점수 : {loop_x:<20} | Hex: {loop_x.hex()}")
print(f"  └─ 판정: 미세 오차가 끝까지 보존되어 동점 해소 => {loop_cross.hex() == loop_x.hex()} (PASS)")

```

##  5. 결론 및 적용 가이드

* **결론:** 대칭 데이터셋 환경에서 `sum()` 내장 함수를 사용하면 C-level 반올림 규칙에 의해 비트 완전 일치가 유발됨. 명시적 `loop()`를 사용하여 행 우선 누적 시 발생하는 **부동소수점 오차 오프셋(ULP)을 보존함**으로써 동점(`UNDECIDED`) 현상을 깔끔하게 해소함.
* **적용:** 프로젝트 내 핵심 MAC 연산 모듈의 파이프라인을 `loop()` 기반 처리 방식으로 대체 변경 완료.
